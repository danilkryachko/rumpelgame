# Agent Memory

This file stores stable project decisions and invariants for agents. Keep it short and factual.

## Project Decisions

- The approved project databases are PostgreSQL and RocksDB.
- Do not introduce, expand, or migrate to another database engine without explicit approval.

## Sensitive Areas

- World generation and chunk serialization must remain deterministic unless explicitly changed.
- Current worldgen determinism is guarded in `server/pkg/world` tests: flat strata, repeat generation, little-endian serialized block order, and `World.ChunkSnapshot()` stability must stay compatible unless explicitly changed.
- Current chunk payload compatibility is guarded in `server/pkg/api`, `server/pkg/world`, and `server/pkg/network` tests: packet field numbers, chunk field numbers, enum wire values, raw default fields, RLE wire vectors, and Go protobuf unknown-field preservation must not regress without an explicit protocol task.
- Current RocksDB chunk persistence is guarded in `server/pkg/storage` tests: key format, signed coordinate key ordering, save/load round-trip, missing chunk behavior, overwrite isolation, and corrupt payload rejection must stay compatible unless explicitly changed.

- Storage and persistence changes require extra review before finalizing.
- Rust GDExtension changes can affect client behavior and performance; review them carefully.
- Client startup readiness telemetry is split into one-shot wall-clock timestamps `startup_chunk_packet_ms`, `startup_chunk_inserted_ms`, `startup_chunk_loaded_ms`, `startup_mesh_queued_ms`, `startup_mesh_dispatched_ms`, `startup_first_mesh_ms`, `startup_collision_ms`, and `startup_player_spawn_ms`; movement gates should preserve that nondecreasing order and keep `startup_packet_read_work_ms`, `startup_packet_decode_work_ms`, `startup_packet_reader_elapsed_ms`, `startup_packet_queue_lag_ms`, `startup_chunk_decode_work_ms`, `startup_first_mesh_work_ms`, `startup_first_mesh_phase_ms`, and `startup_first_mesh_collision_work_ms` as work-duration/scheduling evidence separate from wall-clock startup timestamps.
- After Godot observes the local server listening, the main scene attaches `GameClient` after one frame by default; `RUMPELMC_CLIENT_ATTACH_DELAY_SEC` is a diagnostic rollback/control for adding an explicit post-listen delay.
- Server chunk delivery order is nearest-first by default. `RUMPELMC_SERVER_CHUNK_ORDER=directional` is opt-in and only applies movement-direction tie-breaks among chunks at the same distance; it must not change protocol, chunk payload format, storage, world generation, view distance, batch size, or bootstrap radius.
- Rust client packet queue metrics are observational drain-depth proxies over the existing unbounded reader-thread channel. They must not be treated as a backpressure/drop/reorder policy without a separate explicit design change.
- Current chunk compression decision is RLE default with `RUMPELMC_SERVER_CHUNK_ENCODING=raw` rollback. Do not add another compression format until representative non-flat terrain entropy or latency evidence justifies it.
- Current streaming protocol plan is no schema change. Future packet variants must use new oneof tags greater than `3`, and future `ChunkData` fields must use new field numbers greater than `5` with compatibility tests and rollback documented first.
- Resident-set growth gates are stress-only measurement runs. They may raise server view distance and client keep distance inside scripts, but must not change default gameplay draw distance, visible quality, protocol, storage, world generation, or chunk serialization without a separate explicit task.
- Client chunk unload remains keep-distance plus grace based by default. `RUMPELMC_CLIENT_CHUNK_UNLOAD_GRACE_SEC=0` is an immediate-unload rollback/control path; unload churn metrics are telemetry only and must not be treated as a new unload policy without pop-in/collision evidence.
- World pop-in metrics are report-only player-neighborhood probes around the current chunk. They may count missing loaded chunks and loaded-but-collision-missing chunks, but must not become fail gates or policy changes until explicit budgets are defined.
- Player spawn remains collision-gated. Movement readiness summaries may separate render-ready and collision-ready evidence, but they do not authorize lazy collision or reduced collision coverage without an explicit opt-in experiment and gates.
- Client collision radius remains `1` by default. `RUMPELMC_CLIENT_COLLISION_CHUNK_DISTANCE=0` is an opt-in lazy-collision experiment only and must not be promoted while pop-in collision-missing evidence is high.
- GPU terrain render shader assumptions matter: vertex code computes terrain lighting from packed face normals and lighting push constants, fragment code applies the passed lighting to atlas color with opaque alpha, perf markers expose the sanitized `gpu_light_*` values, and scene depth uses reverse-Z `GREATER_OR_EQUAL`.
- GPU terrain partial dirty upload is default-on when `RUMPELMC_GPU_TERRAIN_PARTIAL_DIRTY_UPLOAD` is unset; explicit `RUMPELMC_GPU_TERRAIN_PARTIAL_DIRTY_UPLOAD=0` is the full-rebuild rollback/control path.
- GPU terrain buffer repack must remain default-off behind explicit `RUMPELMC_GPU_TERRAIN_BUFFER_REPACK=1`; unset or `0` keeps the current allocator path until planner tests, allocator gates, profiling artifacts, and rollback behavior justify any broader rollout.
- Visual smoke lighting variants are smoke-only controls. They must not change default scene lighting, draw distance, terrain quality, protocol, storage, world generation, or chunk serialization; use marker fields such as `lighting_variant` plus `gpu_light_*` before comparing captures.
- GPU-native terrain shadows remain behind `GPU_TERRAIN_NATIVE_SHADOW_IMPLEMENTED=false`. While runtime markers report `native_shadow_implemented=0`, env-on captures must stay on `shadow_path=godot_proxy` with `native_shadow_requested=1`, `native_shadow_active=0`, `native_shadow_fallback=1`, `native_shadow_resource_status=disabled`, and zero native-shadow resource lifecycle plus coverage counters.
- Godot scene/resource/import files should not be reformatted casually.

## Agent Roles

- Research agents are read-only and should return concise findings with file paths.
- Review agents look for risks, regressions, missing tests, and code degradation.
- Protocol/world review is required for networking, storage, world generation, chunk serialization, persistence, or Rust extension changes.
- The main agent decides what to change and remains responsible for the final patch.
